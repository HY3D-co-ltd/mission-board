# mission-board — 직원 교육 웹 현황판

`mission-board`는 직원 교육·미션 운영을 웹으로 보여 주는 **공개 배포 저장소**입니다. 운영 기록과 웹을 만드는 소스는 비공개 [mission-loop](https://github.com/HY3D-co-ltd/mission-loop)에 있습니다.

## 두 저장소의 역할과 연결

| 저장소 | 목적·내용 | 수정·이용하는 곳 |
|---|---|---|
| [mission-loop](https://github.com/HY3D-co-ltd/mission-loop) | 직원별 교육 계획, 미션 이슈, 제출·질문·첨삭·판정, 운영 지침, 웹 생성·검증·배포 소스 | 운영 원본과 웹 기능을 수정하고 과제를 제출하는 곳 |
| [mission-board](https://github.com/HY3D-co-ltd/mission-board) | 원본에서 생성한 암호화 웹 페이지와 공개 이용 안내 | 직원·대표가 배포된 웹을 보는 곳 |

```text
mission-loop의 교육·미션 기록과 필요한 교재
  → 웹 생성·암호화 → 복호화·화면 검사 → mission-board 배포 → 실제 주소 확인
직원은 웹에서 안내·현황을 확인
  → 비공개 회차 폴더에 파일 저장 → 본인 미션에 커밋 링크 댓글
  → AI 교육 팀장 첨삭·판정 → 다음 갱신에 웹 반영
```

[hy3d-strategy](https://github.com/HY3D-co-ltd/hy3d-strategy)는 회사 전체 전략·조사·실무자료 저장소입니다. 교육 교재를 포함한 지식의 출처이며, 이 웹의 배포 상대 저장소는 `mission-loop`입니다.

## 직원이 시작하는 방법

1. AI 교육 팀장이 전달한 **전체 접속 링크**로 웹을 엽니다. [기본 주소](https://hy3d-co-ltd.github.io/mission-board/)만으로는 내용이 열리지 않을 수 있습니다. 링크의 열쇠 부분을 공개 게시하거나 임의로 바꾸지 않습니다.
2. 소속과 본인 이름을 선택합니다. 6명 이름·소속은 사전등록되어 있으며 GitHub 등록 댓글 없이 내 교육 계획과 교재를 볼 수 있습니다. 이름이 없으면 AI 교육 팀장이나 가까운 동료에게 확인을 요청하고 공통 교재부터 시작하세요.
3. 내 교육에서 교재를 열어 한 단계씩 실습하세요. 처음에는 Orca에서 Claude Code로 첫 응답을 확인하고 다음 시간에 Codex로 이어갑니다. 중단할 때 개인 연습 폴더의 `학습진행.md`에 멈춘 지점과 다음 할 일을 적으세요. 새 대화에서는 이 파일부터 읽습니다.
4. 과제에서 **에이전트 제출 요청문 복사**를 눌러 개인 에이전트에 전달하세요. 본인 GitHub 계정으로 비공개 저장소의 회차 폴더에 결과물·해당 과제의 실제 대화 사본·검증·제출기록·학습진행 사본을 저장하고, 본인 미션에 커밋 링크를 댓글로 남깁니다. GitHub 업로드 화면에서 직접 올릴 수도 있습니다. [직원 에이전트 제출 규칙](https://github.com/HY3D-co-ltd/mission-loop/blob/main/문서/직원-에이전트-제출규칙.md)
5. 보드에서 최근 회차의 저장 기록과 AI 교육 팀장의 첨삭을 열어 다음 연습을 확인하세요. 저장 기록은 게시 시점의 비공개 저장소에서 집계합니다. 브라우저의 읽기 체크, 직원의 이슈 댓글, AI 교육 팀장의 공식 판정은 각각 따로 확인합니다. [진행 기록과 제출 운영](https://github.com/HY3D-co-ltd/mission-loop/blob/main/문서/교육-제출운영.md)

이름 선택은 이 기기에 기억됩니다. 현재 미션 보드에는 Google 로그인 메뉴가 없습니다. 본인 GitHub 계정 연결과 쓰기 권한은 제출할 때 확인합니다.

직원이 웹을 이용하려고 이 저장소의 코드를 복제할 필요는 없습니다. 두 저장소의 역할을 이해하고, 본인 미션과 필요한 교재에 접근하면 됩니다.

AI 교육 팀장은 실제 과정에 맞춰 다음 연습이나 업무용 시작 프롬프트를 제공합니다. 결과 통과와 독립 수행 역량은 구분하고, 본인이 수행한 근거와 다음 연습을 중심으로 안내합니다. 전체 세션 원문을 이 공개 저장소에 올리지 않습니다.

교육 공지와 사례는 목적·실행 방법·필요한 지원이 잘 전달되도록 편집합니다. 실제 사례를 교육용으로 편집한 예시와 직원의 실제 수행 기록은 구분합니다.

## 직원의 에이전트에게 줄 요청문

```text
너는 내 학습과 업무를 돕는 보조자야.
mission-loop와 mission-board의 README를 읽고
운영 원본·웹 화면·과제 제출 위치를 구분해 줘.
내 이름/팀은 [이름/팀], 미션은 [이슈 링크 또는 첫 배정 준비 중]이야.
내 계정으로 접근 가능한 자료만 확인하고 읽지 못한 자료는 알려 줘.
개인 연습 폴더의 학습진행.md와 내 미션의 최신 댓글·완료 기준부터 읽고
필요한 교재를 찾아 조사·기획·실습·검증을 단계별로 도와줘.
실제 결과와 확인 기록을 남기고 같은 미션에 제출·재제출하게 도와줘.
AI 교육 팀장으로 가장하거나 스스로 통과 판정하지 마.
```

## 개발·운영 에이전트가 수정할 때

- **mission-loop에서 시작합니다.** 해당 저장소의 README와 적용 지침, 운영 지침을 읽고 최신 원본을 확인합니다. 이 저장소의 생성된 HTML을 직접 수정해 운영 원본으로 삼지 않습니다.
- 원본 변경을 기록한 뒤 `mission-loop`에서 `python -X utf8 scripts/publish.py`로 생성·검사·배포·실제 주소 확인을 진행합니다. 실패한 검사를 건너뛰어 배포하지 않습니다.
- 교육·개인 운영 데이터는 암호화해 배포합니다. 공개 README에는 이용 방법과 저장소 관계만 적고, 인증키·접속 열쇠·직원 기록·회사 내부 자료를 넣지 않습니다.
- 기존 공유 링크의 열쇠와 배포 구조를 임의로 바꾸지 않습니다. 판정 기준과 GitHub 댓글 형식은 mission-loop의 운영 지침을 따릅니다.
- 이 README의 관리 원본은 [mission-loop/문서/현황판-README.md](https://github.com/HY3D-co-ltd/mission-loop/blob/main/문서/현황판-README.md)입니다. 안내를 수정할 때도 원본에서 고칩니다. 게시 상태와 배포 절차의 최신 검증 결과는 mission-loop에서 확인합니다.
